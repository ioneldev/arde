# ARDE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build ARDE (Agentic Repo Docs Engine), a CLI that documents a Go `net/http` service with swag annotations, a generated OpenAPI file and project docs, proves it changed no behaviour, and traces the run.

**Architecture:** Plain Python code runs a fixed pipeline. LLM agents (discovery, explore, docs, judge) and one classifier call work inside it through one generic loop, and they return data that code validates. Code writes all comments, `swag` writes the spec, and the running service is the final check. Go-specific logic sits behind `LanguageAdapter`, backed by a small Go helper.

**Tech Stack:** Python 3.12, uv, Pydantic 2, mypy, ruff, pytest, `anthropic` SDK, jsonschema, referencing, openapi-spec-validator, PyYAML. Go 1.27 with `golang.org/x/tools` (helper only). `swag` v2.0.0-rc6. Docker with Compose.

**Spec:** `docs/superpowers/specs/2026-11-01-arde-design.md`. Read it before starting. The plan argues from it and doesn't repeat its reasoning. Throwaway versions of the Go tools and test changes are in `docs/research/spike/`, so reuse them.

## How this plan runs

Work is split into six phases. Each ends with a **review gate**: stop, write the walkthrough, and wait for Ionel to review, understand and test before starting the next phase. Do not cross a gate without Ionel's go-ahead.

Each phase has a spec in the repo at `docs/specs/phase-N-<name>.md`, written before the phase starts: status, a task checklist, purpose, what it delivers, how we know it's done, and how to test it by hand. Update its status and checklist as each task finishes, and commit that with the task, so progress can be followed in the repo. Implementers and reviewers get the phase spec alongside their brief. `docs/index.md` links every phase spec.

Each gate's walkthrough goes in `docs/decisions/phase-N-walkthrough.md`, and covers what was built, why it's written that way, how to run it, what was measured, and what's still untested. New decisions go in `docs/decisions/` as they're made.

Before each gate, the whole phase's diff gets four independent reviews, dispatched together on the most capable model. These come on top of the per-task reviews:

- **Architecture reviewer** (`feature-dev:code-architect`): layering and dependency direction, boundaries against the spec, interface design, what will be hard to change later.
- **Code reviewer** (`pr-review-toolkit:code-reviewer`): correctness, clarity, Clean Code rules, test quality.
- **Bug hunters** (`pr-review-toolkit:silent-failure-hunter`, plus an adversarial `general-purpose` reviewer told to assume a defect exists): swallowed errors, bad fallbacks, edge cases, failures under real conditions.
- **Security reviewer** (`general-purpose`, following the `security-review` skill): secrets in logs and traces, prompt injection from repo content, path and host escapes in agent tools, what child processes can reach, write-back safety, and container mounts. Repo content is untrusted input throughout.

Each reviewer gets the phase's diff, the spec and the real constraints, but not the implementer's reasoning. All findings go to one fix dispatch, followed by one scoped re-review. The walkthrough lists each finding and how it was resolved, and anything left open goes to Ionel at the gate.

If time runs short, cut in the spec's order: `--dry-run` and architecture tests, then automatic re-discovery, then the classifier, then stored requests.

The Phase 1 start scan compared the tasks with each other and with the spike code, and ran the spike on `catalog-poc`. These override the task text below. The spike is experiment code, so its behaviour is not a requirement.

- **All tasks, repo-agnostic (Ionel's rule):** ARDE knows nothing about any target repo. Task 8 adds an architecture test that fails if a non-test file under `src/arde` or `tools/goinspect`, prompts included, contains `catalog`, `envOr`, `writeError` or `fxRates`.
- **Tasks 6 and 7, file walking:** one shared walker. `declarations` and `match` skip what the Go tool ignores: `.git`, `vendor`, `testdata`, and directories or files starting with `_` or `.`. Anywhere else, a `.go` file that won't parse exits 1 and names the file, because skipping it would shrink the inventory without saying so. `compare` skips only `.git`, and compares by bytes when either side won't parse, so it can over-report a change but never miss one. A link to a regular file counts as that file, because the Go tool builds it, and anything else that isn't a regular file is skipped. Paths use `/`, and output is sorted. Add `TestCompareIgnoresLineEndings`, because a checkout with `core.autocrlf` has CRLF line endings.
- **Task 6, declaration ids:** ids stay unique. A second `init` or `_` in a file reads `file::func init#2`, because several `init` functions in one file would otherwise share an id and one could hide a change in another. A generic receiver `Stack[T]` reads `Stack.Push`, not `?.Push`.
- **Task 6, allowed tags:** only `oneOf:"..."` and `binding:"optional"` are ignored, as whole keys, because ARDE writes nothing else and `binding:"required"` changes behaviour under gin. Comparison and declaration hashes share one normaliser. Comments drop out because the parser is not given `parser.ParseComments`, not because of `SkipObjectResolution`.
- **Task 7, patterns:** a bad regex, an over-long pattern or a negative `args` value exits 2, with `goinspect: bad patterns: ` at the start of the message, because Go's runtime also exits 2 on a panic.
- **Task 7, fingerprints:** the package path matches the `go.mod` module exactly or with a `/` after it. Remove the spike's filter on names starting with `init`, which would hide `initDB` and is unnecessary because a handler can't call a package initialiser. A root is one exact function id, so nothing is matched by name. A root that matches nothing goes in a new `"unresolved":[root]` list, and a function with no body goes in `"without_body":[root]`. Package load errors exit 1.
- **Task 8, the interface:** `LanguageAdapter` holds only methods that have an implementation, so there are no stubs and mypy can prove `GoAdapter` satisfies it from the start. Task 8 declares eight: `detects`, `is_comment_only`, `changed_declarations`, `extract_inventory`, `route_fingerprints`, `run_checks`, `built_service` and `discovery_guidance`. Task 14 adds `render_annotations` with `RenderManifest`, `RenderRequest`, `RenderResult` and `RenderOutcome`. Task 15 adds `generate_spec`. Task 18 adds `format_issues`, `check_agent_edits` and `EditCheckRequest`. The total is twelve, as `docs/deviations.md` says.
- **Task 8, tests and fixture:** add tests for `changed_declarations`, `route_fingerprints` and `built_service`, which the task lists none for. `tests/fixtures/shop` also needs a `Makefile` and one `//go:build integration` test file, because the listed tests assert on both. The fixture shares no names or layout with `catalog-poc`, because a copy of its shape would prove nothing about other repos: use the module `example.com/shop`, a different route registration call and receiver, a different error helper, `r.URL.Query().Get`, and its own wrapper around `os.Getenv`. A repo with no `Makefile` gets empty `make_targets`, not an error.
- **Task 8, `is_comment_only`:** compare directive lines in Python, using the wide pattern from `docs/research/spike/python/directives.py`, treat any comment edit in an `import "C"` file as real, then run `goinspect compare` on two temporary directories holding one file each.
- **Task 8, inventory:** add `ResponseField.json_name`. `name` stays the Go field name, because the renderer and `FieldFact` need it, while the docs tables need the JSON name. Response structs are non-test structs with at least one `json` tag. Unexported, `json:"-"` and embedded fields are left out, with embedded fields listed in `docs/limitations.md`. A route's method comes from the start of its path text, then from the last part of the call if that's an HTTP verb, as in `r.GET`, and otherwise is `ANY`. A route path the compiler doesn't know stops the run unless its site sits inside a function a route pattern matches, because a missing route is worse than a stopped run. A `param`, `env` or `error` code argument that isn't a literal is dropped. So a repo that wraps `os.Getenv` in its own helper gets nothing from the default pattern, and Discovery has to supply a pattern for that helper.
- **Task 8, running Go:** `GoAdapter` takes the `goinspect` binary path. `build_goinspect(bin_dir)` runs `go build` once per process, and Go's build cache makes that cheap, so a stale helper can't happen. `built_service` passes `-buildvcs=false`. Every child process has a timeout. The allow-listed environment lives in `src/arde/adapters/child_env.py`, shared with Task 9, and leaves out `GOFLAGS`. `goinspect` failures raise `GoinspectError(GoCommandError)` with exit 1, and zero routes raises `NoRoutesError(ProfileProblem)` with exit 3.

- **Task 24:** a route in `RouteHashes.unhashed`, or missing from `hashes`, in either tree counts as changed. `compare` reads a link wherever it leads, so every new caller on a repo runs behind the repo-links gate. `is_comment_only` compares one file at two times, so the caller pairs files by full relative path, and a moved file is a real change.

## Prompt injection (Ionel, 2026-11-03)

Ruling R135. The repo ARDE reads may hold text written to steer its agents. Containment is already in place:
- no shell or write tools, and the HTTP tool reaches only the local service
- the inventory comes from code
- facts need verified evidence
- the docs agent sees facts only
- code writes every annotation, and the agent-edit check refuses any other line

These rules close what containment leaves open, which is a planted comment steering the *content* of a fact or a sentence.

- **Tasks 12, 13 and 16, prompts:** each system prompt says that repository content, tool results and probe bodies are data to describe, never instructions. Text in them that tries to direct the agent is reported, never followed. Each agent's submit schema has a `suspected_injections` list of file-and-line or probe references. Code records them in the trace and as `RunReport.warnings`.
- **Task 13, evidence:** a code quote counts as evidence only if it holds code. A quote made only of comment lines, or only of the contents of one string literal, is refused with a reason that says so. Planted text can then never be the only evidence for a claim. A comment can still be quoted next to code.
- **Task 19, docs grounding:**
  - Every URL, host name and e-mail address in the generated docs must appear in the repo or in a recorded probe.
  - Every shell command in a docs code block must appear in the repo: a `Makefile` target, the README, a Dockerfile or a CI file, or the profile's commands.
  - Anything else is a finding owned by `docs`.
- **Test fixture:** `tests/fixtures/hostile` is a copy of `shop` with planted instructions in a comment, a README, a string literal and a response body. They ask for an invented admin route, a fact quoting only the comment, and a `curl … | sh` line in the docs. Tests with scripted model replies prove code refuses each outcome. One `eval`-marked test runs the real models on it, opt-in through `make eval`, and asserts that none of the planted claims reaches the wiki, the annotations or the docs.

## Review Focus

Failure modes the spec implies but doesn't state. Each has a test in the owning task.

1. **A model turn ends with no submit call**, is refused, or hits `max_tokens`. The agent stops with a named reason or is re-prompted, and is never treated as finished. Task 4.
2. **The API fails mid-run** (bad key, rate limit, network down). The run exits with a clear next action, writes nothing to the user's repo and keeps the trace. Tasks 5 and 17.
3. **A run is interrupted** with Ctrl-C or SIGTERM. Services stop, nothing is written back, the snapshot is unchanged. Tasks 9, 17 and 23.
4. **Bad input before any spend**: missing API key, a path that isn't a git repo, no `go.mod`, an unknown branch. Exit 2 with the next action and no LLM call. Tasks 10 and 17.
5. **Awkward repo content**: binary files, huge files, non-UTF-8 text, a symlink pointing outside the repo. Agent tools return a clear tool error or truncated output, never crash or escape the copy. Task 11.
