# Architecture

This is the short map. The reasoning and the measurements are in the [design](superpowers/specs/2026-11-01-arde-design.md).

**Status:** The first run works end to end. Phase 0 built the domain models, the agent loop, the Anthropic client, the tracer, the cost cap and the model settings. Phase 1 built the Go helper, the Go language adapter and the service runner. Phase 2 built the pipeline and the cli: `uv run --env-file .env arde --repo <url or path> [--branch B] [--json] [--max-usd N]` resolves the source, learns the profile, explores the running service, annotates the handlers, generates the OpenAPI file and writes the docs. Phase 3, as scoped for 2026-11-03, added the checks and a repair loop of one round. A URL run leaves its result as a commit on a branch of the workspace clone, and a local run leaves it in the run's output copy. A re-run reuses the saved profile and wiki and asks Explore only for the facts whose declarations, routes or files changed. Not built: the classifier, the stops for a run with no real change, the blind judge, write-back to a local repo and the container. The steps below mark them.

## The orchestrator is code

Python code runs a fixed sequence of steps. Agents work inside it only where the next action depends on what they find. Every agent is the same generic loop, configured with a system prompt, a tool list, a submit tool with a validator, and limits. Validation errors from the submit tool go back to the model as tool results, which is how an agent corrects itself. See [decision 0001](decisions/0001-orchestrator-is-code.md) and [decision 0010](decisions/0010-agent-contract.md).

| Step | Kind | Sees | Tools |
|---|---|---|---|
| Discovery | Agent | Repo files | list files, read file, grep, submit profile |
| Explore | Agent | Repo files, profile, inventory, change report, the running "before" service | list files, read file, grep, HTTP probe, add facts, finish facts |
| Docs | Agent | Wiki facts and the probes they cite, never code. On a repair, also the findings | submit section |
| Classifier (not built yet) | One model call | The diff plus code measurements | None, structured output |
| Judge (not built yet) | Agent | Docs, spec and the running "after" service only | predict and call, finish |

## A run

```
Every run:
  resolve source -> copy into the run folder -> baseline build, vet, test
  -> profile: the saved one if it still fits, else discovery writes one
     and code validates it
  -> inventory from code -> compare with the snapshot (a later run)
  -> explore builds the wiki, or updates the stale facts
  -> copy the input to an output copy -> render comments and tags -> swag
  -> docs agent writes sections
  -> code checks (a finding goes back to its owner, then the output is
     written again and checked again: 1 repair round)
  -> commit on a branch of the workspace clone (a URL source)
  -> save profile, wiki, manifest, sections and snapshot
```

A later run differs in three places. The saved profile is checked again by building and starting the service, and Discovery runs only when it no longer fits. The input is compared with the snapshot, so Explore is told which facts are stale. The last run's pages are copied from the snapshot into a clone that holds none, so the docs agent writes again only the sections whose facts changed.

Not built yet: the classifier, the stops for a run with no changes or with only comment changes (Explore and the checks run anyway), the blind judge, write-back to a local repo and the container.

A run stops on any of these:

- the turn limit of an agent (defaults: discovery 15, explore 30, docs 8 per section, judge 30)
- the cost cap (default $10 per run)
- the repair round used (one by default, `REPAIR_ROUNDS` in `src/arde/application/repair.py`), a round that brings back the same findings, or a finding owned by code or discovery

A failed run exits non-zero, leaves the user's repo untouched, keeps the old snapshot and writes a report.

## Layers

Each layer is a folder under `src/arde/`, created by the task that first needs it, except the cli, which is one file.

| Layer | Holds | Where |
|---|---|---|
| domain | Frozen Pydantic models and pure rules: facts, inventory, findings, the stale rule | `src/arde/domain/` |
| application | The pipeline, the agent roles, and the ports (interfaces) they need | `src/arde/application/` |
| checks | One file per verification check | `src/arde/checks/` |
| adapters | The LLM client, the Go language adapter, the workspace, the service runner, the tracer, the console | `src/arde/adapters/` |
| cli | The command line. It wires adapters into the application | `src/arde/cli.py` |

What exists today:

- `src/arde/domain/`: the frozen models and pure rules. `base.py` holds `Frozen`, the constrained text types that keep a name from a repo or a model to one safe line, and the helpers that write a control character out. `facts.py` is the wiki: five kinds of fact, each with evidence and links, the probes its facts cite, and the eight topics. `inventory.py` is what code extracts from the source. `profile.py` holds `DiscoveredProfile`, which Discovery may set, and `RepoProfile`, which adds the `extra_test_commands` only the owner may. `change.py` holds `ChangeReport` and the stale rule. `findings.py` holds `Finding` and its four owners: discovery, explore, docs and code. `report.py` holds `RunReport`, `RepairRound` and the exit codes. `errors.py` holds `ArdeError`, the one error the pipeline catches, with `SourceError` and `DiscoveryFailed`. `usage.py` and `pricing.py` hold token counts, each model's price and the cost of a call.
- `src/arde/application/agent_loop.py`: the one loop every agent runs, plus `record_model_call` and `record_failed_call`, which trace and charge every paid call, failed or not.
- `src/arde/application/ports.py`: the `LLMClient`, `Tracer`, `LanguageAdapter`, `ServiceRunner`, `ServiceClient`, `AgentToolbox`, `RunStore` and `SourceControl` interfaces. `LanguageAdapter` holds fourteen methods, each with an implementation: it detects a repo, says what Discovery must know about the language, tells a comment-only edit from a real one, lists changed declarations, extracts the inventory, fingerprints routes, renders the annotations and tags the facts call for, runs the repo's own checks, builds the service for as long as a `with` body needs it, generates the OpenAPI file from the repo's annotations, lists the files its formatter would change, checks a run's edits, says what a quote from a file holds, and names the version of each tool it runs. `RenderRequest` and `RenderOutcome` carry a render: the outcome's `RenderResult` says what changed in each file, measured before and after, and its `RenderManifest` lists the comment lines ARDE wrote, which the next render removes first. `EditCheckRequest` carries the two copies, the render's result and the manifest the render was given. `SourceQuote` carries a quote and where it appears, and `QuoteContent` says what it holds. `SourceControl` copies the source into a run and commits the result on a branch of the workspace clone. `ProfileProblem` lives here too, the one error the application may send back to Discovery: anything else an adapter raises means the repo or the machine is broken. `ServiceRunner` has one method, `running`, which takes a `ServiceConfig` and hands out a `ServiceHandle` (the base URL and the port). The errors a runner raises, `ServiceStartError`, `ServiceDiedError` and `ServiceStopError`, live here too, because the application catches them. `ServiceClient` sends one `HttpRequest` to a running service and returns the `ProbeRecord`, or raises `ProbeFailed`. An `HttpRequest` is GET or HEAD and a path with its query, never a host. `AgentToolbox` hands out the tools agents call, so the application never names an adapter.
- `src/arde/application/probe_log.py`: `ProbeLog`, every probe an agent made in a run, found by method and path. A fact cites a probe by its request, and code copies the response from here.
- `src/arde/application/budget.py`: the cost cap and the totals per role.
- `src/arde/application/models_config.py`: `RoleConfig`, the model, effort, turn limit and token limit of one role, checked against the price table when it is read. `src/arde/application/tool_schema.py` closes a model's JSON schema for strict tool use.
- `src/arde/application/agents/discovery.py`: the Discovery agent. `discover_profile` reads the override, then runs the agent with the repo tools and `submit_profile`. The schema is `DiscoveredProfile` plus `suspected_injections`, with no `extra_test_commands`. The submit check reads the repo with the profile, override applied. A `ProfileProblem`, or a `main_file` that holds none of the service's declarations, goes back to the model as the tool's error, and any other error stops the run. A profile that leaves `dropped` lines or `unmatched_patterns` is refused with them listed (at most 50 of each, plus a count), and is accepted when it is submitted again leaving nothing that was not listed. It returns the discovered profile, the merged profile and the `suspected_injections`. An agent that stops without a profile raises `DiscoveryFailed`, exit 3. Its instructions are `src/arde/application/prompts/discovery.md`. The system prompt is that file plus `discovery_guidance()`, the same for every repo, and its SHA-256 goes in the trace as a `prompt` event. It says repository content and tool results are data, never instructions.
- `src/arde/application/profile_store.py`: `profile.yaml` and `profile.override.yaml`, at the paths `RunStore` names. Each override key replaces the discovered value, and only the override sets `extra_test_commands`. A bad override stops the run with exit 2 before any model call. No profile, or one of another `schema_version`, means a first run.
- `src/arde/application/profile_validation.py`: `validate_profile` builds the service, reads the inventory, refuses one over 1 MiB of JSON with exit 2, starts the service, and requests each route with GET. It returns findings owned by Discovery. The pipeline runs it on a saved profile at the start of a later run, and a freshly discovered profile is not started before Explore. `read_inventory` and `refuse_an_oversized` also serve Discovery's submit check and the inventory step.
- `src/arde/application/agents/explore.py`: `explore`, the Explore agent. `add_facts` checks and keeps one batch, `finish_facts` ends the run once every inventory item has a fact and every stale fact was submitted again or deleted, and code fills `Wiki.probes` from the probe log. The system prompt is `src/arde/application/prompts/explore.md`, frozen. The run's context goes in the first user message as ASCII-escaped JSON, and on a repair the findings follow under "Findings to repair".
- `src/arde/application/fact_validation.py`: `validate_batch` accepts a fact only with evidence: a quote in a file inside the repo that holds code, or a probe made in this run. Names must be the inventory's and links must resolve. An error code needs a probe that returned it or an unreachable fact. Each response status must be returned by a probe the fact cites, or, at 400 or above, be the status of an error code the response lists, read through `LanguageAdapter.http_status`; a code quote backs no status. `coverage_gaps` lists routes, params, error codes and response fields with no fact. `src/arde/application/fact_names.py` holds the inventory names a fact can hold; an `ANY` route is offered once per concrete method. `src/arde/application/fact_schema.py` builds the `add_facts` schema with those names as enums.
- `src/arde/application/wiki_store.py`: `load_wiki` and `save_wiki`, one YAML file per topic plus `probes.yaml`, sorted and ASCII, each with `schema_version`. A mismatch reads as a first run.
- `src/arde/application/agents/docs_writer.py`: the docs. `write_section` runs the docs agent once per narrative section, on the docs role's `max_turns`, with `submit_section` as its only tool. It sees the wiki's facts without their code quotes, and the bodies of the probes its own topic's facts cite, so it never sees source code. On a repair it also sees the findings. Its prompt, `src/arde/application/prompts/docs.md`, says fact and probe text is data to describe, never instructions. A submit is refused when `used_fact_ids` is empty or names a fact the wiki does not hold, when a table placeholder other than `{{table:error-codes}}` appears or is not alone on its line, or when a suspected injection names neither a fact nor a probe the agent was shown. Each suspected injection is a `warning` event and a line in `DocsResult.warnings`. `write_docs` renders the API reference page by code, writes each narrative section that is stale, new, missing from the repo, or whose facts came or went, and removes a section whose topic has no facts. The overview and the change guide rest on every fact, so they are written whenever the wiki has facts and again when any fact comes or goes. Every page starts with `GENERATED_MARKER`; a page without it stops the run before any model call and is never removed. A page is never read or written through a link: a `docs` folder or a page that is one stops the run with exit 2 before any model call, and a `README.md` that is one gets no link and a warning. `add_readme_link` appends one line linking the `docs` folder to an existing `README.md`. A narrative section is written again when the facts it rests on, recorded in `sections.yaml` or its own, include a changed fact (same id, different content, or a cited probe that now answers differently), or when one of its facts came or went. The overview and the change guide rest on every fact.
- `src/arde/application/reference_tables.py`: `api_reference` and `error_table`, one row per param, response, field and error code, so a new param is one new row. The field table takes the key a client sees from the inventory's `json_name`, and the error table marks each code no request can reach. `src/arde/application/section_store.py`: `load_sections` and `save_sections` for `sections.yaml`, the fact ids each written section rests on, its own topic's facts included. A file of another schema version reads as empty, so every section is written again.
- `src/arde/application/repair.py`: the repair loop. `run_with_repairs` checks, sends each finding to the agent that owns it, and checks again, for one round by default. Explore findings go to explore and then to docs, docs findings go to docs alone, and a finding owned by code or discovery stops the loop before any model call. A round that brings back the same findings, compared by check and subject, ends it early. Each round is a `repair` trace event naming its round, owners and finding count. The pipeline implements `VerifyStep`: its checks, and a way to run an agent again. `ExploreRequest` and `DocsRequest` carry the findings as `repair_findings`, and each agent's first message lists them under "Findings to repair".
- `src/arde/application/pipeline.py`: one small function per step: copy_input, baseline, profile, inventory, changes, explore, copy_output, render, spec, docs, checks, commit and save. A red baseline stops before any paid call. The checks step runs through `run_with_repairs`. Each check starts the before and after services for that attempt and stops them when it ends. An explore repair runs explore again on this run's wiki, with the findings and its own service on the input copy. The docs repair ends every round, so it writes the whole output again on a new copy of the input: annotations and spec from the latest wiki, and the pages with the findings, with the topics explore changed counted stale. A finding left after the last round exits 1 and commits nothing. The profile, wiki, manifest, sections and snapshot are saved only after every check passes. `report.json` lists each round under `repair_rounds`, the summary prints a line per round, and the trace shows a `repair` event followed by the steps run again. The report keeps each warning once.
- `src/arde/application/changes.py`: compares the input copy with the snapshot. A file that differs only in comments counts as unchanged, the README is compared without the link ARDE added, and a file only the snapshot holds in the `docs` folder is ARDE's own. It lists the facts whose links changed as stale, `changed_topics` names the topics whose facts changed, and `restore_last_pages` copies the last run's pages into a clone that holds none. `src/arde/application/run_warnings.py` writes the warnings a run carries, one line each: what the repo's own checks left unproven, and what the profile found and could not use. `src/arde/application/manifest_store.py` keeps the render manifest in `render_manifest.yaml`. `src/arde/application/pipeline_deps.py` holds what the steps share, built once by the cli. `src/arde/application/checks_runner.py` holds `Check`, `CheckContext` and `run_checks`, which runs every check so one failing check never hides what the others found.
- `src/arde/adapters/llm/anthropic_client.py`: the Anthropic API behind `LLMClient`. `src/arde/adapters/llm/fake.py` is `FakeLLM`, a scripted stand-in for the model, so tests run the real loop with no network.
- `src/arde/adapters/language/go/`: the Go language adapter, which holds every Go idiom. `adapter.py` is `GoAdapter`. It adds default patterns to every profile: `os.Getenv` and `os.LookupEnv` for env, and `URL.Query().Get`, `PathValue`, `FormValue`, `PostFormValue` and `Header.Get` on any one identifier for params, so a param read in `net/http`'s own spellings needs no pattern from Discovery. `goinspect_client.py` builds the helper and reads its JSON replies into typed models. `inventory_builder.py` turns the helper's replies into the inventory, keeping only what belongs to the service. `directives.py` and `makefile.py` hold the comment-only rule and the make targets. `discovery_guidance.py` holds what Discovery must know about Go, so no prompt has to. `toolchain.py` runs build, vet and test, and builds the service. `go_test_events.py` reads the stream of `go test -json`, so a result says which tests ran and which skipped, not only that none failed. `swag.py` builds the pinned `swag` and runs `swag init --v3.1 -g <main-file> --requiredByDefault --ot json,yaml -o docs` from the repo root, which writes `swagger.json` and `swagger.yaml` into the repo's docs folder and no `docs.go`. Only swag's exit code decides, because it warns on runs that went well. `renderer.py` writes the swag annotations above each route's anchor and above `func main`, a comment above each described field, and the `oneOf` and `binding:"optional"` tags, at positions `declarations` gives, after removing what the last run wrote. `templates.py` holds the text of each comment line, written so swag reads exactly the fact and the next comparison reads an ordinary comment. `struct_tags.py` edits a tag the way `goinspect`'s normaliser reads one, and `gofmt.py` lays out a file again when it was laid out before the render and lists the files `gofmt -l .` flags or cannot parse. `edit_checks.py` checks that a run changed only what ARDE writes. `goinspect compare` sees code, and a line allow-list sees directives: each line the output gained is one the render reported, or an input line with ARDE's tag pairs added or taken out, and each line it lost is an annotation, a manifest line or an empty comment. Lines are compared as the renderer measures them, through `unmatched_lines` in `renderer.py`. A changed `go.mod`, `go.sum`, `go.work` or `go.work.sum` is a finding. `quotes.py`: `quote_content` reads a quote with Go's lexical rules, or a Makefile's comments and quoted strings, and refuses a quote from a file the service is not built from, from a Makefile make does not read, or a path not written as `list_files` writes it. `versions.py` records the version of `go`, `swag` and the helper for the trace. `errors.py` holds the errors these files raise or name, `output_limits.py` how much of each command's output is kept, and `timeouts.py` how long each command may run.
- `src/arde/adapters/child_env.py` and `src/arde/adapters/child_process.py`: every child process gets an allow-listed environment, never a copy of ours, and a timeout that also stops what the child started. A child's output goes to temporary files and is read back with a limit, so a chatty command costs disk, and memory only up to that limit. `src/arde/adapters/child_text.py` makes that output safe to show: a message keeps its last 2,000 bytes, and a control character is written out as `\xNN`. `child_env.py` holds the generic list and no Go variable, so a service started to be probed gets none, and `src/arde/adapters/language/go/go_environment.py` builds the Go commands' environment on it.
- `src/arde/adapters/repo_links.py`: the gate every `GoAdapter` method that takes a repo calls first. It lists each link whose real path leaves the repo's real path and stops the run, naming the link and never its target. It names no language.
- `src/arde/adapters/source.py`: the first step of a run. `resolve_source` clones a URL into the repo's workspace with `core.autocrlf=false`, on the branch `--branch` names, after asking the remote whether that branch exists. A local path must be the top of a git repo, and it is never written. `copy_tree` copies the files `git ls-files --cached --others --exclude-standard` lists, so uncommitted and untracked work comes along and ignored files such as `.env` do not, copies every file before it makes any link, copies each link as a link, and runs the links gate on the copy. A local tree is untrusted, `.git` included: git runs with the allow-listed environment and `core.fsmonitor` off, the links gate walks the whole tree before git runs, and an index entry that leaves the repo, or two names that are one path once case and Unicode form are ignored, stop the copy. `ensure_git_eol_config` gives the `-c core.autocrlf=true` a CRLF checkout of LF files needs. `commit_result` commits a URL run's result on `arde/run-<run id>` in the workspace clone, with ARDE's own identity, no signing and no hooks, and never pushes; `GitSourceControl` is the one `SourceControl`. The repo id comes from the origin URL, the same for each spelling of one remote, or from a hash of the folder's path when there is no `origin`.
- `src/arde/adapters/workspace.py`: `Workspace`, the one `RunStore` (a port in `ports.py`), which names the files of one repo's workspace under `ARDE_HOME` (default `~/.arde`) and gives each run a folder, `runs/<run id>/`, with `input/`, `output/`, `report.json`, the service logs and `trace/` (mode 0700) holding `trace.jsonl` and `debug.log`. The snapshot and the clone are links, each replaced by one rename, so a run stopped at any instant leaves the last one whole.
- `src/arde/adapters/service_runner.py`: `LocalServiceRunner`, the one `ServiceRunner`. It reserves a free port by binding port 0 and closing, starts the binary itself (never through a make target) in the folder `ServiceConfig.cwd` names, in its own process group, with the allow-listed environment plus the port variable, and sends its output to a log that only the owner can read and that must be a plain file. It then waits for a TCP connection, with no health route. A service that exits first fails at once with its exit code and the end of the log, and one that never opens the port fails after `timeout_s`, naming the port variable and the log. When the body ends, whether it returned, raised or was interrupted, it first notes whether the service had already exited by itself, then sends SIGTERM to the whole group, waits 5 s, and kills the group twice, because on macOS one kill can miss a child being forked at that instant. It then checks that the port no longer answers. A service that had died raises `ServiceDiedError`, and one that survives the stop, or whose port still answers after it, raises `ServiceStopError`. Either is attached to the body's own error as a note when there is one. The process-group code is shared with `child_process.py`, and this file names no language and no repo.
- `src/arde/adapters/repo_tools.py`: `list_files`, `read_file` and `grep`, the read-only tools an agent has on a repo. One guard resolves every path a tool opens, links included, and refuses it unless it stays inside the repo, so a link that leads out is neither listed, searched nor read. `grep` matches text as written, not a regex, because the model picks the pattern and the repo the text. Every result goes through `clean_repo_text`, which writes out each control character but the line break and the tab.
- `src/arde/adapters/http_tool.py`: `http_probe`, the agent's one tool on a running service, and `LocalServiceClient`. Code joins the model's path to the service's own address and sends it with `http.client`, which neither follows a redirect nor rewrites `+` or `%2B`. Each reply goes to the `ProbeLog` whole, and the model sees a cut body.
- `src/arde/adapters/agent_toolbox.py`: `LocalToolbox`, the one `AgentToolbox`.
- `src/arde/adapters/tracer.py`: writes `trace.jsonl` and `debug.log`, and `redacted_report` gives the report with the key replaced.
- `src/arde/adapters/models_file.py`: reads the model settings per role from `src/arde/config/models.yaml`, or from the file `ARDE_MODELS_FILE` names. A missing or misspelt role or setting, and a repeated key, are refused before any model is called.
- `src/arde/adapters/console.py`: what a person sees. A line on stderr as each step starts and ends, then the summary (on stdout after a success, on stderr after a failure), or the report alone as JSON with `--json`. It prints one line per repair round, and writes out every control character.
- `src/arde/checks/`: one file per check, each owning its findings. `behaviour.py` holds `Behaviour`: the edit check, the repo's own build, vet and tests on the output, and `compare_responses` over every recorded probe plus a GET for each route without a placeholder, each sent to the before and after services. `routes.py` holds `RoutesUnchanged`, and `formatting.py` holds `FormattingUnchanged`, which flags only files newly flagged. All three are owned by code. `spec_valid.py` validates the spec as OpenAPI 3.1. `spec_inventory.py` holds `SpecMatchesInventory`, which compares the spec and the wiki with the inventory both ways: every route and param the spec names, and every field and error code the wiki names, must be one the code holds, every route with a function to annotate must reach the spec, and every error code the code sends must reach the wiki. A route whose fact is in the wiki but whose operation is missing from the spec is owned by code, because no agent can bring it back. `live_contract.py` holds `LiveContract` and `boundary_requests`. Starting from a request that succeeded while Explore probed the route, it sends the "after" service each enum value and one outside it, each bound of a query param and the value just past it, the value just past each bound of a path param, and each default against the omitted param, and it checks every reply against its closed schema. It sends GET and HEAD alone, so an `ANY` route is requested with the GET and HEAD the spec lists on its path. `closed_schema.py` holds `close_schema`, which adds `unevaluatedProperties: false` to every object schema that lists its properties, so a key the spec does not name fails, and `ClosedSchemas`, which validates a reply against the spec's closed components. `spec_operations.py` reads the spec into `Operation`s. `docs_grounding.py` holds `DocsGrounding`: every URL, link, e-mail address and host with a port in the pages the run wrote must appear in the repo's text or a probe body, and every line of a code block must be a make target, be written in the README, a Dockerfile, a CI file or a Makefile, or be a command the owner added to the profile. `markdown_text.py` reads the code blocks and link destinations of a page by hand, with no Markdown library.
- `src/arde/cli.py`: the one place that wires adapters. It reads the key into a `SecretStr`, refuses bad input before any work, resolves the source first, because the workspace is named after its repo id, and turns SIGTERM and SIGHUP into Ctrl-C. It exits 0 on success, 1 on a red baseline, a finding or a provider error, 2 on bad input, 3 when Discovery needs input, 4 when the cost cap is passed, and 130 when interrupted.
- `tests/fixtures/`: small `net/http` services that the adapter tests treat as real repos, sharing no names or layout with any repo ARDE was built against. `shop/` is one service behind a wrapper, whose price reply holds a field that is one of two structs, depending on the item. `parcels/` holds two `main` packages that share code, and a route added by a blank import. `library/` mounts two muxes, one behind middleware. `annotated/` holds hand-written swag annotations and the two tags ARDE adds, with its `main` in a folder of its own, so the spec tests need no renderer. `hostile/` is the shop with instructions planted in a comment, the README, a string literal and a reply body. `tests/fixtures/mutations.py` holds the changes the design measured its checks against, made on a copy of `shop`, one named function each.
- `tools/goinspect/`: the Go helper. `compare` lists the Go files that changed, ignoring comments, formatting, line endings and the two struct tags ARDE adds. `declarations` hashes every top-level declaration and lists struct fields. `match` applies the profile's call patterns to every non-test Go file and prints each call that matches, with the value of each argument that is a string literal, and each pattern that matched nothing. Both skip what the Go tool leaves out, such as a folder with its own `go.mod` or a file whose build constraint requires the `ignore` tag. `routes` reads the service through the type checker: `main_package` and the packages of its module that it imports. It lists those folders and every call that registers a route, with the one function each route's docs belong on and every function of the module its handler names, so a route cannot be lost by a pattern that names too little. It needs a repo that compiles. `fingerprints` takes the function ids `routes` prints, and hashes everything each one reaches by static calls, closures included, so a later run knows which routes changed.
- `tools/swag/`: a Go module with no code, whose `tool` line pins `swag` v2.0.0-rc6 and whose `go.sum` holds the hash of every module it needs. `build_swag` builds it once per process into ARDE's own folder, so nothing is installed globally.

Imports go inward. These rules are enforced by `tests/test_architecture.py`:

- The domain imports no adapter, application or cli code.
- The application imports no adapter or cli code. It reaches the outside world through ports.
- The checks import no adapter or cli code.

The same test file keeps Go-specific code and words such as `go.mod`, `omitempty` and `oneOf` out of everything except the Go language adapter, in Python and in Markdown prompts, keeps reads of the plain API key to the adapter, the tracer and `tests/conftest.py`, and keeps product code and prompts from naming a repo ARDE was tried on. A small Go helper, `goinspect`, sits next to it for AST work and the call graph. The orchestrator talks to Go only through the `LanguageAdapter` interface, so another language could be added later.

## What the LLM may and may not do

It may discover how a repo is built, explore what a service does, and write documentation prose from facts. Once they are built it may also label a change and judge usability.

It may not write a comment or a spec line, pick a shell command, or touch a file. Code renders every annotation from facts, `swag` generates the spec, and code checks every rule. See [decision 0003](decisions/0003-code-enforces-rules.md).

## Where run state lives

Each target repo gets one workspace holding its profile and the owner's override, wiki, `sections.yaml`, the render manifest, last snapshot, the clone of a URL source, and a folder per run with the run's copies, the trace, logs and `report.json`. Deleting the workspace means the next run is a full first run. The terms are in the [glossary](glossary.md).
